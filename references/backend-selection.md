# 出图方式选择与 API 检查

仅出图任务在环境检查前执行；只讨论方案、改文案、审查已有图片时跳过。
优先级：本次明确选择 > 项目已记录方式 > 用户保存的偏好 > 首次询问。已有星幕项目沿用原路线，不每次重新询问。

首次问“你想用星幕画布，还是 API 直连出图？”不提供服务商菜单、预设服务地址或默认模型。
选择 API 后：
1. 收集用户自己的 API 地址。
2. 引导通过宿主安全输入或本机环境变量 DETAIL_FLOW_API_KEY 配置 Key，不要求贴进聊天，不显示明文。
3. 收集用户指定的图片模型名称。仅在有已核实的只读模型列表时供用户选择真实返回的模型；不擅自替换。
4. Agent 查看该地址对应的公开文档或 OpenAPI，匹配 [已有协议](api-execution.md)。不能根据域名、模型名称、HTTP 200、模型列表或“兼容 OpenAI”宣传就认定图片接口兼容。没有足够证据即“无法确认兼容”，停止；不自动编写新适配器。
5. 根据文档记录准确路径、所选模型参考图能力、参数限制，生成非敏感配置。运行 image_api.py check CONFIG RECEIPT：检查 Key、配置并调用文档明确的只读鉴权接口。无安全只读验证方式时不发送付费探针，判为未通过。
6. 通过后才进入商品分析、方案审核、后续生成。说明“接口兼容检查通过，实际出图效果尚未验证”。配置成功不是付费授权。

不通过时：“这个 API 地址目前无法用于本 Skill 出图：<实际原因>。”然后停止。区分协议不支持、参考图能力未确认、Key 无效、模型不可用、连接超时；不把暂时失败说成永久失效。不自动换星幕、不推荐替代站、不扩展适配开发；用户更新配置后才重查。

非敏感配置存到用户既有偏好位置，否则 ~/.detail-flow/backend.json；项目记录 detail-flow-backend.json。Key 只存在本机环境或宿主密钥设施，不能写进配置、HTML、日志、发布包。不修改宿主语言模型配置。
后续复用配置，必要时做只读检查，不重复收集三项。地址、模型、协议或参数能力变化后重新匹配。历史任务保留原配置。
API 模式不安装、不启动、不检查星幕。沿用共享审核工具的必要依赖。方案交付说明中展示主机、模型和尺寸，不显示 Key 或带签名 URL。媒体上传和费用遵守实际授权。

地址原样按服务文档核实，不要求一定包含 /v1。模糊模型名或多个候选时让用户选择准确 ID，不擅自选变体。新增媒体遵循当前使用者指定的工作、临时和交付目录，不预设盘符。
